PRIVACY & SAFE USE

Just enough detail.
A little more care.

Understand what this coursework prototype records and how to use it safely.

What we collect and why

Your username, email and a password hash support your account. Item listings describe belongings received by staff. Private identifying details, claim evidence and review messages support staff assessment. Collection authorisations confirm a particular handover.

Who can see what

Public visitors see only item listings. Claimants see their own evidence and outcomes. Property officers and administrators can read claims and private item details to review ownership. Administrators also see application security events and manage account access.

Protection and its limits

Private identifying details, claim evidence and review messages are encrypted in the database. Passwords are hashed; collection codes are stored as digests. A server with access to the encryption key can decrypt private records. The local development server uses HTTP on this computer; HTTPS deployment remains a separate task. This prototype has not been certified secure or compliant with privacy law.

Please keep sensitive information out

  • Use fictional data while testing.
  • Never submit passwords, device PINs, identity numbers, payment details, or other people's personal information.
  • Describe identifying marks privately; don't put them in public item descriptions.
  • Give collection codes only to an authorised property officer during collection. Replacing a code invalidates the previous code.
  • Sign out on shared devices. No legitimate staff member needs your account password.

Activity records

We record account actions, claim outcomes, access denials, staff evidence access and handovers. Audit events exclude claim text, passwords and collection codes. Abuse counters use keyed identifiers and short-lived counters rather than storing raw IP addresses or attempted usernames in the application audit trail. The development web server also writes request paths to its console.

Retention and requests

The local operator controls this prototype's data. Contact that operator to request an account/data review. There is no self-service deletion or automatic retention schedule in this version. Before real use, define the actual controller, contact channel, retention periods, deletion and backup procedures, and assess applicable Malaysian privacy requirements.

Staff judgement remains necessary

A matching description or valid collection code is not a guarantee of physical ownership. Staff must assess evidence and confirm the approved claimant in person. The system records that process; it cannot independently prove every ownership claim.
